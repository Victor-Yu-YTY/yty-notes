# SQL-Executor 规则维护指南（standards/README.md）

> 一句话：**改判定标准 = 改 `standards/executor.md`，不用改代码、不用重启服务**；
> 但改完**必须**跑通 `python scripts/selfcheck.py`，用例与该文档一起提交。

本目录只有两样东西：

| 文件 | 作用 |
| --- | --- |
| `executor.md` | **判定标准的唯一事实源**：阈值表 + 环境表 + 全部检查项 |
| `README.md` | 本文件：怎么加规则、改规则、停用规则、改完怎么验 |

代码侧只有 `src/sql_executor_mcp/spec.py`（解析与校验）和 `engine.py`（求值），
规则内容一个字都不在代码里。

---

## 一、文件结构

```text
**标准版本**：2026-11-04     ← 展示用，建议改规则就改日期
**规则版本**：1              ← 整数，规则语义变更时 +1（进审计与 /healthz）
**引擎**：exec-v1            ← 固定值，代码校验，别改
**模式**：live               ← live=判定并执行；shadow=只判定不执行

## 阈值
| 名称 | 值 | 说明 |

## 环境
| 环境 | 开放执行 | 允许类型 | 执行窗口 |

## 任意分组标题（如「通用规则」）
### EX-G01 标题
- **级别**：block
- **适用**：all
- **判定**：stmt_kind not in $allowed_types
- **说明**：{stmt_kind} 未开放执行……
```

规则块以 `### EX-xx 标题` 开头，**`## ` 或 `### ` 标题即结束上一条规则**，
所以规则之间不要写别的小标题。

## 二、新增一条规则

1. 在合适的分组里加一段：

```md
### EX-A11 ALTER 表选项变更

- **级别**：block
- **适用**：alter_table
- **判定**：alter_ops intersects (TABLE_OPTION)
- **说明**：ALTER 表选项（ENGINE / ROW_FORMAT / AUTO_INCREMENT / COMMENT）无法自动回滚，本版不支持
- **原因**：反向语句无法从表结构快照推导，放行等于给出一个回滚不了的变更
```

2. **编号必须唯一**，格式 `EX-[GTAINU]两位数字`：G=通用、T=建表、A=变更表、
   I=建索引、N=插入、U=更新。新号往后排，**不要复用已删除的号**。
3. `级别` 只接受 `block` / `warn`（也接受 `❌` / `⚠️`，分别等同前两者）。
4. `适用` 写 `all`，或逗号分隔的语句类型：`create_table, alter_table,
   create_index, insert, update`。
5. `说明` 里可用 `{事实名}` / `{阈值名}` 占位符，渲染时替换；**占位符必须是
   已注册的事实或阈值，否则加载即报错**。
6. `原因` 可选，用于解释规则存在的原因；当「缺失」触发拦截时，它会作为提示文案。
7. `样例` 等其它字段只作说明，解析器直接忽略，不影响判定。

> **需要新事实怎么办？** 事实由代码在 `facts.py` 的 `FACT_SPECS` 里注册、在
> `collect_*` 里采集。判定表达式只能引用已注册的事实，写不存在的事实名会在
> 启动/热加载时直接报错——这是有意的，避免规则引用了取不到的数据还以为在判。

## 三、修改一条规则

直接改那一行，三种常见改法：

| 想改什么 | 改哪里 |
| --- | --- |
| 阈值（行数、字节、秒数、GB） | 只改 `## 阈值` 表，**所有引用该阈值的规则自动跟着变** |
| 某条规则的判定条件 | 改该规则的 `判定` 一行 |
| 提示文案 | 改该规则的 `说明`（占位符别删错） |

环境开放范围只改 `## 环境` 表：

- `开放执行 = false`：该环境一条语句都不放行（判定阶段即 BLOCKED，不连库）；
- `允许类型`：只决定本环境开放哪几类语句；**能碰哪个库由账号 GRANT 决定，不在这里配**；
- `执行窗口`：只对「超大表 MODIFY COLUMN」生效（EX-A06），写 `-` 表示不限。

## 四、停用一条规则（不删也行）

在该规则里加一行：

```md
- **停用**：true
```

服务加载时跳过它：不出现在 `list_checks`、不参与判定。
**建议**：下线规则时把「停用」写清并留一句原因，比直接删掉更好追溯。

---

## 五、`缺失` 字段（fail-closed 的唯一例外通道）

事实取不到时（例如 MySQL 没有内置剩余磁盘查询，`disk_headroom_gb` 永远拿不到），
判定结果是「三值里的 None」。这时按下面处理：

| `缺失` 取值 | 行为 |
| --- | --- |
| 不写（默认） | `block` 级规则 → **按命中处理**（fail-closed）；`warn` 级规则 → 跳过 |
| `warn` | 按风险提示处理，不影响结论 |
| `skip` | 跳过，连提示都不出 |

默认口径是 **fail-closed（取不到就当有问题）**，只有确实取不到的事实
（如磁盘空间、COUNT 超时）才显式写 `skip`，且必须在 `原因` 里写清为什么。

## 六、判定表达式语法

一条规则一个布尔表达式，可用的写法：

| 写法 | 含义 |
| --- | --- |
| `事实 = 值` / `事实 == 值` | 相等 |
| `事实 != 值` / `事实 <> 值` | 不等 |
| `事实 > $阈值` / `>=` / `<` / `<=` | 数值比较 |
| `事实 in (a, b)` / `事实 not in (a, b)` | 属于 / 不属于集合 |
| `事实 intersects (A, B)` | 与集合**有交集**即命中（如 `alter_ops`） |
| `事实 set (A, B)` | 两个集合**完全相等**才命中 |
| `事实 is null` / `is not null` | 取不到 / 取得到 |
| `事实 is empty` / `is not empty` | 列表为空 / 非空 |
| `事实 is true` / `is false` | 布尔判断 |
| `A and B` / `A or B` / `not A` / `(A or B) and C` | 组合，支持括号 |

取值可以是：数字、`true` / `false` / `null`、不带引号的标识符（如 `COPY`、
`MODIFY_COLUMN`、`InnoDB`）、带引号的字符串（`'x'`），或 `$变量名`
（阈值或环境配置项）。

## 七、改完怎么验（必做）

```bash
# ① 只验标准文件本身：解析、校验、44 条用例集、离线执行路径
python scripts/selfcheck.py

# ② 看当前生效的规则与阈值（服务起来后）
curl -s http://127.0.0.1:8040/healthz | jq
#   → rules_count / block_count / warn_count / standard_sha256 应同步变化
```

`selfcheck.py` 覆盖：

- 标准文件能否解析、编号/级别/表达式/事实/占位符校验是否通过；
- `tests/cases/basic.yaml` 用例集（每条用例注入一份「事实」，断言 BLOCKED/READY
  与命中的检查项 id）；
- 执行路径（写前落盘、事务、双道行数守卫、回滚 SQL 生成）离线跑通，不连库。

**用例与 `executor.md` 必须一起提交**：改规则不改用例，等于评审时看不到行为变化。

---

## 八、发布流程

1. 改 `executor.md`（必要时同步 `tests/cases/basic.yaml`）；
2. `规则版本` +1，`标准版本` 改成当天日期；
3. `python scripts/selfcheck.py` 全绿；
4. 覆盖服务器上的 `standards/executor.md`（**不必重启服务**，下一次请求即生效）；
5. `curl /healthz` 确认 `standard_sha256` 已更新、`policy_warning` 为空；
   若热加载失败，服务会继续用上一版并在响应里带 `policy_warning`，按提示修文件即可。
