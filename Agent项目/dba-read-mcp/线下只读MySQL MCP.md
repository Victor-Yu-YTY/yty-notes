# 项目记录：线下环境只读 MySQL MCP 接入 AgentSpec 体系

> 本版本：只描述**架构与机制**，不含域名、接口路径、端点清单、内网地址、服务标识、账号与凭据。
> 记录日期：2026-10-23　｜　服务版本：`v0.2.3`

---

## 一、一句话

把只读的 MySQL 元数据/查询能力做成 MCP 服务，接入 AgentSpec 体系：**外部 Agent 按 Skill 说明书办事，先向身份平台换 300 秒临时凭证，再经受管网关调用；MCP 只负责干活。**

```
身份平台发证  →  受管网关验票转发  →  MCP 服务执行
```

---

## 二、三方分工

| 角色 | 只负责 | 不负责 |
| --- | --- | --- |
| **AgentID（身份平台）** | 身份、凭证签发与核验、授权声明 | 业务能力 |
| **agent-tools-gateway（受管网关）** | 唯一受管入口、验票、能力目录与契约发布、协议适配、请求流水号 | 业务逻辑、数据权限 |
| **db-read-mcp（MCP 服务）** | 业务实现、只读防护、结果结构、审计 | 验人、发凭证 |

**硬边界**：MCP 不直接面对调用方，调用方也不知道 MCP 地址；只有网关能访问 MCP。

---

## 三、身份平台的作用

| 项 | 内容 |
| --- | --- |
| 是什么 | 管理 Agent 身份、凭证、授权、封禁与审计的平台 |
| 永久凭证 | 平台签发、绑定真人账号；**只发给身份平台，永不交给网关** |
| 临时凭证 | Agent 用永久凭证申领，**有效期固定 300 秒**，与目标入口地址绑定，不可延长 |
| 授权声明 | 通过"变量编组"在签发时冻结（如能力所属的 `mysql_scope`，声明可访问的环境），调用时不可另行申报 |
| 逐请求核验 | 网关每来一个请求都回调核验：验有效性、验归属链、取回冻结变量 |
| 拒绝语义 | 无凭证 / 凭证无效 / 凭证不属于本入口 / 已撤销 / 被封禁 / 封网期 |
| 对本次项目的意义 | **"能查哪个环境"由凭证绑定的编组决定，不是 MCP 自己判断** |

本机接入所需两个配置项：平台地址（含固定路径后缀，取值为 `<身份平台地址>`）+ Agent 永久凭证。

## 四、受管网关的作用

| 功能 | 具体 |
| --- | --- |
| 唯一入口 | `http://<受管网关地址>`；外部只能走这里，禁止直连上游 |
| 能力目录 | 列表页展示所有已启用能力及其实现类型与操作数 |
| 契约页 | 每个能力的操作清单、参数 Schema、返回 Schema、调用示例 |
| **协议适配** | 把远程 MCP 包成**普通 HTTP 接口**，调用方**无需 MCP 客户端** |
| 验票 | 逐请求回调身份平台；无凭证由网关在协议层之前直接拒绝 |
| 统一信封 | 返回体固定为 `{数据、请求流水号、状态}` 三段，流水号是验收的唯一锚点 |
| 上游隔离 | 上游地址不对外暴露，调用方只知道网关 |
| 服务标识 | 网关自身在身份平台的登记号（用于凭证绑定与核验） |

### 4.1 本能力在网关上的 9 个操作

- 全部为 `POST` + JSON 体，单次超时 15 秒；
- 路径形如 `<网关地址>/<统一前缀>/<能力标识>/<操作名>`，**能力标识为 `mysql`**；
- 9 个操作如下（参数与返回 Schema 以网关契约页为准）：

| # | 操作名 | 用途 | 属性 |
| --- | --- | --- | --- |
| 1 | `list_environments` | 列出可用环境（所有查询的第一步） | 只读 |
| 2 | `list_databases` | 列出某环境的库 | 只读 |
| 3 | `list_tables` | 列出某库的表 | 只读 |
| 4 | `describe_table` | 字段与索引结构（最常用） | 只读 |
| 5 | `get_create_table` | 完整建表语句（DDL） | 只读 |
| 6 | `search_column` | 按字段名反查库/表 | 只读 |
| 7 | `run_select_query` | 执行一条只读 SELECT | 只读 |
| 8 | `explain_query` | 对只读 SELECT 做执行计划分析 | 只读 |
| 9 | `refresh_metadata` | 刷新元数据缓存 | 仅改缓存（**不产生业务数据变更**） |

> 契约页把第 9 个标注为"可写"，原因就是它改了服务内部缓存。

### 4.2 MCP 是怎么"埋"在网关后面的

| 环节 | 做法 |
| --- | --- |
| 注册类型 | 在网关上按**远程 MCP** 类型登记（不是普通方法、不是脚本） |
| 固定上游 | 指向 db-read-mcp 的 MCP 入口（`<MCP 内网地址>`，**仅网关可达**；调用方既看不到也连不上） |
| 操作映射 | MCP 的 9 个工具 **1:1** 映射成 9 个操作接口 |
| Schema 来源 | 网关读取 MCP 的工具定义，渲染成契约页的请求/返回 Schema |
| 对外暴露面 | **只有普通 HTTP，没有对外暴露 MCP 入口** → 调用方不需要装 MCP 客户端 |
| 变量编组 | 登记 `mysql_scope`，声明可访问的环境 |
| 鉴权分工 | 调用方的临时凭证**在网关处验完即止**，不向下游透传；网关用自己的准入令牌访问 MCP |
| 隔离收益 | 换上游地址/换实现，只要改一条网关注册，**调用方完全无感** |

## 五、db-read-mcp 的作用与实现

### 作用

面向三个线下环境（`dev` / `test` / `stage`，MySQL 8.0.32）的**只读**元数据与查询服务，9 个操作与 §4.1 一一对应。**不接入生产环境；不提供任何写操作。**

### 实现要点

| 层 | 做法 |
| --- | --- |
| 部署 | 统一运行目录（遵循本方向 MCP 存放规约）；进程守护双单元（主服务 + 联调期假鉴权）；密钥仅经环境变量注入，目录内无明文 |
| 协议 | Streamable HTTP 形态的 MCP 服务，入口路径结尾斜杠不可省略 |
| 鉴权第 1 层 | 服务准入令牌（头名 `<准入令牌头>`），缺失或错误 → **在协议层之前直接返回 403**；改名后保留旧头名双读兼容 |
| 鉴权第 2 层 | 用户身份与环境权限，转发内部鉴权平台校验；**逐请求实时校验，拒绝结果不缓存** |
| 只读三重防线 | ① 语法树校验（仅放行查询类语句，禁多语句、禁导出文件、禁锁读、禁系统库）② 会话级只读 ③ 数据库只读账号 |
| 硬限制 | 查询默认 200 行、上限 1000；语句超时 3 秒；单值超 2000 字符截断 |
| 数据访问 | 按环境隔离连接池（懒建立）；系统视图参数化查询 |
| 缓存 | 本地库六表：元数据 TTL 3600 秒，查询结果 TTL 300 秒且默认不启用 |
| 审计 | 按天切分的 JSON Lines，写入失败不阻断业务 |
| 结果导出 | 每次调用结果落文件，附签名下载链接、限期失效 |
| 健康检查 | 免鉴权接口返回服务名，用于链路自检 |

## 六、Skill 的定位与调用

| 项 | 内容 |
| --- | --- |
| 是什么 | **纯文本说明书**，存放于 AgentSpec 仓库的技能目录下；不是代码、不是接口 |
| 谁读它 | 外部 Agent：总入口规范 → 技能索引 → **只读命中的那一份说明书** |
| 里面写什么 | 何时该用/不该用、前置校验、换凭证步骤、调用方式、强/弱判据、失败分支、证据表 |
| 里面不写什么 | 代码、令牌、数据库口令、**上游地址**（只说"由网关托管、地址不对外"） |
| 为什么必须 | 规范要求"有 Skill 才是放行依据"；命中零个则直接失败，禁止自建流程或直连 |
| 索引登记 | 技能索引第一节登记一行，含标识、解决什么问题、何时需要读、维护者、入口路径 |

## 七、外部 Agent 的完整调用流程

```
0. 读规范      总入口规范（已加载进规则）→ 查技能索引 → 只读命中的说明书
               ↓ 输出「入口回执」三行：来源 / 命中 / 动作（含仓库+分支+sha，给不出即终止）
1. 前置校验    有永久凭证？环境名合法？库表名合法？是否"改结构/改数据"（是 → 立即中断）
               ↓
2. 核对登记    向身份平台查询「可用的受管入口」
               核对：服务标识、入口地址、凭证交付方式、变量编组
               ↓
3. 换票        向身份平台申领临时凭证（提交服务标识 + 目标入口 + 编组变量）
               → 成功即得 300 秒凭证（原文使用，不加 Bearer 前缀）
               ↓
4. 调用网关    向网关发起「操作调用」（能力标识 + 操作名）
               头：携带临时凭证原值；体：业务参数
               ↓
   ┌───────────┴────────────────────────────────────┐
   │ 网关：持凭证回调身份平台核验 → 通过               │
   │ 网关：带准入令牌转发 → MCP 校验令牌 → 执行        │
   │ 网关：封装信封（数据 + 流水号 + 状态）返回        │
   └───────────┬────────────────────────────────────┘
               ↓
5. 取值判据    按实际嵌套层级取值，先判成功标志
               强判据：字段名集合 / 索引名集合与预期一致；建表语句含目标表名
               ↓
6. 出证据      逐操作记录 状态 / 请求流水号 / 判据强弱 / 是否截断
               三态结论：成功 / 失败 / 受阻（含原因），不得报"部分成功"
```

**该链路已完成端到端实测：无凭证被拒 → 换票成功 → 调用成功。**

## 八、对外部 Agent 的监管是怎么实现的

监管不是靠一个开关，而是**五道闸门串成一条链**，任何一环不通过，调用就到不了数据：

| 闸门 | 在哪 | 怎么实现 |
| --- | --- | --- |
| **① 谁能用** | 身份平台 | 只对有效注册用户名下的有效 Agent 发放凭证；统一准入，风险压在"接入侧"（由人类决定哪些能力接进来） |
| **② 以谁的名义** | 身份平台 | 凭证绑定**真人账号**，核验时回传调用主体；规约禁止借用他人凭证 |
| **③ 能做什么** | 身份平台 | 授权在**签发时冻结**（编组里的环境等声明），调用时不可另行申报；一张票只对一个目标入口有效 |
| **④ 此刻还算不算数** | 网关 + 身份平台 | **逐请求**回调核验，**不缓存拒绝、不凭既往成功放行**；封禁/撤销/封网**即时生效** |
| **⑤ 有没有按要求办事** | Skill（Agent 自身） | 入口回执（自证读了哪版规范）+ 前置校验 + 禁止绕过/直连 + 三态结论 + 证据表，**不得报"部分成功"** |

**配套的三条可追溯手段**：

| 手段 | 作用 |
| --- | --- |
| 请求流水号（网关生成并回写响应头） | 一次调用的唯一锚点，把"结论"和"证据"绑在一起 |
| MCP 侧审计（按天切分，记工具 / 环境 / 状态） | 事后核对"谁在什么时候查了什么" |
| 身份平台侧审计（核验成功/失败都记，**不含凭证原文**） | 证明"这张票此刻确实被核验过" |

**两个设计上的关键点**：

1. **网关不存会话授权**——每次调用都要票，因此不存在"授权越攒越多"的累积越权；
2. **监管与被监管解耦**——外部 Agent 不需要知道 MCP 在哪，也拿不到数据库凭据，**它的全部自由度都被压在"网关这一层能验的东西"之内**。
