# yty-notes

个人笔记与项目记录。围绕 **数据库运维（MySQL / Oracle）**、**监控告警（Grafana / Prometheus）**、**系统与平台治理**、**AI Agent（MCP 服务）** 几条线，沉淀可复用的方法、命令与踩坑复盘。

主体是可直接对照执行的文档；`Agent项目/` 下另有四个 MCP 的脱敏源码存档，可本地跑离线自检，但开箱不能直接连库（配置需自行补全）。

## 目录结构

```
yty-notes/
├── 学习文档/   概念梳理与工具速查
├── 安装教程/   环境搭建的完整步骤
├── 项目经历/   生产环境项目复盘（背景 → 需求 → 方案 → 成果）
├── Agent项目/  MCP 服务的功能说明 + 脱敏源码存档
│   ├── README.md              工具集总览与共同设计取舍
│   ├── dba-read-mcp/          只读查询（9 个工具）
│   ├── sql-review-ddl-mcp/    DDL 审查（8 个工具）
│   ├── sql-review-dml-mcp/    DML 审查（4 个工具）
│   └── sql-executor-mcp/      DDL/DML 执行（5 个工具）
└── 参考规范/   MCP 编写方法与约定
```

`Agent项目/` 每个子目录的形态一致：一份 `<名称> 功能说明.md` 讲设计，一个同名代码包（如 `dba-read-mcp/dba-read-mcp/`）放 `src/`、`config/`、`scripts/`、`standards/`。

## 阅读约定

- **全部文档已脱敏**：主机名、IP、域名、账号、工单号、看板 UID 等均为 `10.x.x.x`、`grafana.example.com` 这类占位符；方法论和技术结论不受影响。
- **项目类文档结构统一**：背景与需求 → 方案设计 → 实施与验证 → 成果与经验，附关键命令和排障清单。
- 文中代码块可直接对照自己的环境执行，**执行前先看该节的前置检查**。
- **Agent项目 的源码**是脱敏存档：目录结构和规则逻辑完整，但 `config/` 里的地址与凭据是占位值，需替换后才能真正连库。

## 维护

- 新增文档按主题放入对应目录，文件名用中文标题，首行写 `# 标题`。
- 单篇控制在"能独立看懂"的粒度：一篇讲清一个问题，不追求大而全。
- 提交信息说明"改了什么"，例：`新增 systemd 端口收敛记录`、`更新 Grafana 时段阈值写法`。
